# MCP 2026-07-28 compatibility note

## Target

| Item | Value |
| --- | --- |
| Protocol | `2026-07-28` |
| Release date | July 28, 2026 |
| TypeScript SDK | `@modelcontextprotocol/server@2.0.0` and `@modelcontextprotocol/node@2.0.0` |
| Runtime | Node.js 24 LTS |

The MCP team released the stable v2 SDK packages on July 27, 2026 for the `2026-07-28` protocol.

## Wire-level delta

| Area | Legacy 2025-era behavior | 2026-07-28 behavior in this server |
| --- | --- | --- |
| Opening exchange | `initialize`, then `notifications/initialized` | No initialization handshake |
| Client context | Sent once during `initialize` | Protocol revision, client info, and client capabilities in every request's `_meta` object |
| Discovery | The `initialize` result advertises capabilities | The server handles `server/discover` |
| HTTP state | Optional `Mcp-Session-Id` and session lifecycle | Each POST is independent; no session ID |
| HTTP streaming | GET could hold a session stream | GET and DELETE are not MCP transports |
| HTTP routing metadata | Protocol version header | `MCP-Protocol-Version` and `Mcp-Method`; `Mcp-Name` for named calls |
| Cancellation | `notifications/cancelled` on a connection | Closing the response stream aborts HTTP work; stdio still routes cancellation notifications |
| Version mismatch | Initialization negotiation | A modern mismatch returns protocol error `-32022` |

## Modern-only serving

The server uses two v2 SDK helpers in strict mode:

- `createMcpHandler` creates a fresh MCP server for every HTTP request and receives `{ legacy: "reject" }`.
- `serveStdio` pins one modern protocol era per stdio connection and receives `{ legacy: "reject" }`.
- An opening `initialize` request is rejected over both transports. The server does not run the SDK's legacy stateless fallback.

The modern integration test sends `tools/list` as its first request. Separate tests prove that HTTP and stdio reject legacy initialization.

## Tools and resources

- `registerTool` attaches a strict Zod input schema and effect annotations to each tool.
- Successful handlers return `structuredContent` that matches an output schema.
- The SDK turns validation failures and upstream exceptions into MCP tool errors.
- Resources declare private cache hints.
- The server registers tools and resources in a fixed order.

## Lifecycle and cancellation

Every OpenRouter operation receives `ctx.mcpReq.signal`. `OpenRouterClient` combines that signal with a request timeout and removes its abort listener when the request ends. `compare_models` rethrows cancellation instead of returning a partial result.

On `SIGINT` or `SIGTERM`, HTTP mode closes its listener and MCP handler. stdio mode closes its serving handle. stdio logs go only to `stderr` because `stdout` carries protocol messages.

## HTTP security and authorization

This process is a local server. It:

- binds only to `127.0.0.1`;
- applies the SDK's localhost `Host` and `Origin` validation;
- exposes one `/mcp` endpoint;
- does not present a static bearer secret as MCP OAuth.

Do not expose this HTTP listener directly to the internet. A remote gateway must terminate HTTPS and implement the MCP OAuth 2.1 resource-server requirements. Those requirements include protected-resource metadata, audience-bound token validation, and correct `401` and `403` responses.

`stdio` does not use MCP HTTP authorization. Pass OpenRouter credentials to the server process through environment variables.

## OpenRouter compatibility

- The client uses native `fetch` and passes MCP cancellation to each request.
- `HTTP-Referer` and `X-OpenRouter-Title` carry app attribution.
- Chat sends `max_completion_tokens`. The tool still accepts `max_tokens` as a deprecated alias.
- Key usage calls `GET /api/v1/key`.
- Model tools call `GET /api/v1/models` and page the MCP result.
- Model and pricing responses preserve OpenRouter's structured `pricing.overrides` tiers.

## Deliberate non-goals

This update does not:

- publish or deploy the repository;
- register a remote MCP server or edit global Claude and Codex configuration;
- add a session layer over the stateless protocol;
- add OAuth without a real issuer, resource identifier, verifier, and deployment URL;
- make paid OpenRouter calls in tests.
